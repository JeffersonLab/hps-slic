Detailed Description

Class defining a UserAction that forces a primary (generator-level) beam electron to undergo a genuine one-step trident interaction, e- + N -> e- + e+ + e- + N, in a chosen tracker sensor, via Geant4's G4ePairProduction process (direct nuclear-field e+e- pair production off a charged lepton). This process scales linearly with target thickness and dominates the two-step "pseudo-trident" (eBrem followed by pair conversion, which scales quadratically) in thin silicon sensor layers.

G4ePairProduction is not part of the default QGSP_BERT electron physics. This plugin constructs and initializes (via PreparePhysicsTable()) its own private instance of the process at beginRun(), purely as a sampling engine for manual CrossSectionPerVolume()/SampleSecondaries() calls in stepping() – it is never attached to G4Electron::Electron()'s process manager, so Geant4's own per-step dispatch never invokes it (that path requires lambda tables this plugin never builds). No shared physics-list code is touched.

A compensating event weight equal to the real local interaction probability for the traversed slab is written to the MCParticle collection so the forced sample remains correctly normalized. For this plugin's GPS-driven gun, correct weight propagation also required a small fix in TrackManager::saveTrackSummaries() (see that file) so that pre-creating the MCParticle collection here doesn't defeat its geant4Generator detection.

Only the primary beam electron (track parent ID 0) is ever forced. The forced interaction kills the primary and injects three new tracks (the degraded scattered electron and the sampled e+/e- pair), all with a nonzero parent ID, so the forcing can never cascade.
