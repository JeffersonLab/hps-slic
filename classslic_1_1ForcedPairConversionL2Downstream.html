Detailed Description

Class defining a UserAction that forces the primary (generator-level) WAB photon to pair-convert in the downstream (second) sensor of Layer~2, rather than relying on its natural (very small) conversion probability. A compensating event weight equal to the real local conversion probability is written to the MCParticle collection so the forced sample remains correctly normalized.

This is the fourth in the ForcedPairConversion family: ForcedPairConversion (Layer-1 upstream), ForcedPairConversionL1Downstream (Layer-1 downstream), ForcedPairConversionL2Upstream (Layer-2 upstream), and this one (Layer-2 downstream). All four plugins are otherwise identical in structure.

Only the primary photon (track parent ID 0, no creator process) is ever forced. Any photon produced downstream of the forced conversion (e.g. by eBrem on the forced e+/e-) has a nonzero parent ID and is left alone, so the conversion cannot cascade into later layers.

Natural conversion is also temporarily deactivated for the gamma "conv" process while the primary photon transits any of the six upstream sensor volumes – all four Layer~1 sensors (both the upstream and downstream sensor of each half) plus both Layer~2 upstream sensors – so that every event's photon survives all of Layer~1 and the Layer~2 upstream sensor intact and reaches the Layer~2 downstream target instead of some fraction being "wasted" on a natural conversion further upstream. The deactivation is global to all gammas (G4's process activation flag is per particle-type, not per-track), but is only held for the brief window the primary photon is inside one of those six volumes, then restored.

Substrings identifying the individual Layer 2 downstream (second) sensor volumes where the conversion is forced. Layer 2's axial and stereo sensors are separate, non-stacked sibling volumes (not two slabs of one "module"), so the downstream (second) sensor differs by half: for the top half the stereo sensor is downstream (layer index 4 in the LCDD physvolid table), for the bottom half the axial sensor is downstream – the same axial/stereo-vs-layer-parity convention as Layer 1 (see HpsSiSensor). Each substring matches both "..._sensor_volume" (full silicon slab) and "..._sensor_active_volume" (its sensitive sub-volume), but not the enclosing non-sensitive "..._halfmodule_{axial,stereo}_volume" wrapper.
